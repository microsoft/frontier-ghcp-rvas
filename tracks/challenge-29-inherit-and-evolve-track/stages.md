# Inherit and Evolve an Application: Stages

## Stages

| Stage | Name | Difficulty | Est. Time | Key Deliverable |
|-------|------|------------|-----------|----------------|
| 1 | [Establish the Baseline](stage-1-baseline.md) | ⭐⭐ | 30 min | Running starter and recorded test baseline |
| 2 | [Discover the Application](stage-2-discovery.md) | ⭐⭐⭐ | 60 min | Verified workflow-to-code map |
| 3 | [Fix the Cancellation Defect](stage-3-fix.md) | ⭐⭐⭐ | 75 min | Reproduced symptom and regression evidence |
| 4 | [Add the Waitlist](stage-4-feature.md) | ⭐⭐⭐ | 105 min | Persistent waitlist with manual confirmation |
| 5 | [Hand Over the Change](stage-5-handover.md) | ⭐⭐ | 30 min | Brief change summary and working demo |

This track takes **300 minutes**. Run the inherited application before you
change it. Check what the source actually does, fix the support ticket, then
add the waitlist without breaking existing bookings.

> **Short on time?** Keep the UI plain and the working note brief. Do not skip
> the discovery checkpoint or regression proof. If the waitlist is incomplete,
> say so.
