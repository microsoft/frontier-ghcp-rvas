# Developer Onboarding Repair: Stages

## Stages

| Stage | Name | Difficulty | Est. Time | Key Deliverable |
|-------|------|------------|-----------|----------------|
| 1 | [Test Onboarding and Map Failures](stage-1-test-onboarding.md) | ⭐⭐ | 60-75 min | Audience/task map and evidence-based issue inventory |
| 2 | [Define Audience, Structure, and Language](stage-2-define-structure.md) | ⭐⭐⭐ | 60-75 min | Approved information architecture, terminology, and style decisions |
| 3 | [Repair and Test the Core Journey](stage-3-repair-core-journey.md) | ⭐⭐⭐ | 90-120 min | Tested quickstart, tutorial, and corrected reference |
| 4 | [Add Editorial Checks and Maintenance](stage-4-editorial-maintenance.md) | ⭐⭐⭐ | 60-75 min | Link/example checks and an owned maintenance workflow |

The stages follow an editorial repair loop: observe real reader failures,
decide what the documentation should do, repair the core tasks against the
software, then make regressions easier to catch.

> **Short on time?** Complete Stages 1 through 3 and add at least one command
> example to the existing checker. The reader retest is more important than
> polishing every reference description.
